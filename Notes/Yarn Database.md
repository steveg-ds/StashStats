While the Pattern Database serves as Ravelry’s instructional foundation, the **Yarn Database acts as the platform's exhaustive, standardized catalog of physical materials**. In the larger context of Ravelry's platform features, the Yarn Database bridges the gap between digital designs and the physical fiber products required to create them.

Just like patterns, the API treats yarns as highly relational data objects that power personal inventory management, mobile discovery, and community-driven statistics.

Here is how the sources describe the Yarn Database within the broader context of Ravelry's platform features:

### 1. Deep Technical and Material Specifications

The API does not simply store yarn as a text string; it treats it as a complex object with craft-specific technical specifications. When a developer queries a specific yarn (e.g., using the `/yarns/{id}.json` endpoint), the API returns a highly detailed payload:

- **Physical Metrics:** The data tracks exact material constraints, including the weight of a skein in `grams`, its `yardage`, and its `wpi` (wraps per inch).
- **Material Properties:** The API exposes boolean flags for properties like `machine_washable` and `certified_organic`. It also tracks the specific `yarn_fibers` that make up the blend (e.g., 80% Wool, 20% Nylon).
- **Yarn Provenance:** Ravelry tracks the geographical and manufacturing history of the material, exposing `YarnProvenance` data to show exactly where a specific yarn was milled or dyed.
- **Colorways:** Yarns are broken down further into specific `Colorway` objects, which track individual dye lots and color names.

### 2. Standardized Material Taxonomies

To make hundreds of thousands of different yarns searchable, the API relies on standardized, global classification systems. These taxonomies function as public infrastructure that developers are encouraged to cache to improve application performance:

- **`yarn_weights`:** This categorizes yarns by their standard metric thicknesses (e.g., Fingering, DK, Worsted).
- **`yarn_attributes`:** This groups yarns by specific textile properties and structural construction (e.g., "Superwash," "Hand-dyed," or "Gradient").
- **`color_families`:** This provides a standardized classification for dyes, allowing users to search the database by base colors.
- **`yarn_companies`:** The API catalogs the actual manufacturers and indie dyers, exposing endpoints to search for specific companies and retrieve their logos, URLs, and total `yarns_count`. Third-party R packages, such as `ravelRy`, explicitly wrap these endpoints to allow data scientists to search and analyze yarn companies.

### 3. Powering "The Notebook" (Stashes and Projects)

The Yarn Database is heavily integrated into the user's personal "Notebook", transforming abstract product listings into actionable inventory tracking.

- **Stash Management:** When a user logs their personal yarn inventory, the API creates a `Stash` object that is permanently tethered to a master `yarn_id`. This allows the user's personal stash to inherit all the baseline technical data from the master database, while adding their personal `dye_lot`, purchase location, and photos.
- **"Packs" and Project Linking:** When a crafter allocates yarn to a specific project or pattern, the API manages this through an object called a `Pack`. A pack explicitly links a `yarn_id` to a `project_id` or `pattern_id`, allowing the platform to calculate exactly how much yarn is needed or has been used.

### 4. Community Metrics and Third-Party Discovery

Because Ravelry is a social platform, the Yarn Database acts as a repository for aggregated community feedback and mobile utility.

- **Community Feedback:** The API enriches yarn payloads with social metrics, returning the `rating_average`, `rating_count`, and `comments_count` generated by the community. Furthermore, specific `Colorway` objects expose their own `projects_count` and `stashes_count`, allowing developers to see exactly how popular a specific dye color is among users.
- **Mobile Utility:** Because Ravelry does not build its own mobile apps, third-party developers rely heavily on the Yarn Database to build tools for crafters "on-the-go". Applications like _Ravulous_ or _Wooly_ utilize the API's yarn search functionality so that a crafter standing in a physical yarn store can look up a yarn by name on their phone, check the required yardage, and cross-reference it against their queued projects and current stash.
